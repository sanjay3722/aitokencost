## 1. Server vs Client Components

Server Component is the default for every `layout`, `page`, and component.

Add `"use client"` **only** when the component needs one of:

- `useState` / `useReducer` / `useEffect` / refs
- DOM event handlers (`onClick`, `onChange`, …)
- browser APIs (`window`, `localStorage`, `navigator`)
- a client-only library

Rules:

- Push the boundary **down**. A page stays a Server Component; only the
  interactive leaf gets `"use client"`. In this repo that leaf is
  `src/components/Calculator.tsx` — nothing else.
- Server Components can import and render Client Components. Client Components
  cannot import Server Components — pass them as `children`/props instead.
- Never pass non-serializable props (functions, class instances, Dates that
  matter) across the boundary.
- `metadata` / `generateMetadata` exports work **only** in Server Components.

## 2. Async dynamic APIs

In this version these are **Promises**. Always `await`:

```tsx
export default async function Page({
  params,
  searchParams,
}: {
  params: Promise<{ id: string }>
  searchParams: Promise<{ [k: string]: string | string[] | undefined }>
}) {
  const { id } = await params
  const { q } = await searchParams
}
```

Same for `cookies()`, `headers()`, `draftMode()` from `next/headers`.

## 3. Data fetching

- Fetch in Server Components, `async`/`await`, close to where the data is used.
  Parallel-fetch with `Promise.all` when requests are independent.
- Keep secrets server-side. `process.env.X` is read inside a Server Component,
  route handler, or server action — never in a `"use client"` file, and never
  at the top level of anything in `src/lib/` (see §7).
- Client-side fetching (SWR / React Query / `useEffect`) only for data that
  genuinely depends on client state or must poll. The planned `/api/count`
  call from `Calculator.tsx` is the example: debounce it (~400ms) and show the
  local heuristic estimate while it is in flight.

## 4. Caching & revalidation (Cache Components)

`next.config.ts` currently sets **no** `cacheComponents`. If you enable
`cacheComponents: true`, read `08-caching.md` first — it changes the model:

- Mark cacheable work with the `use cache` directive; set lifetime with
  `cacheLife` and tag with `cacheTag`.
- Revalidate with `revalidateTag` / `revalidatePath` from a server action or
  route handler after a mutation.
- Without Cache Components, follow `guides/caching-without-cache-components.md`
  (`fetch` cache options, `export const revalidate`, `dynamic`).

Don't sprinkle `export const dynamic = 'force-dynamic'` to "fix" a caching
bug — find why the route opted out.

## 5. Route handlers & server actions

- Route handler: `src/app/<path>/route.ts`, export `GET`/`POST`/… Validate the
  request body (shape, size, type) before use. Return typed JSON. Read keys
  from `process.env`. Add basic rate limiting for anything that spends money.
- Server action: `"use server"`, validate every input (treat as hostile),
  return a typed result object rather than throwing across the boundary, call
  `revalidateTag`/`revalidatePath` on success.

## 6. Metadata & SEO (Metadata API)

- Static: `export const metadata: Metadata` from `layout.tsx` / `page.tsx`.
  Dynamic: `export async function generateMetadata()`.
- Set `metadataBase` once in the root layout (done: `https://aitokencost.dev`)
  so OG/canonical URLs resolve.
- Use the file conventions for the rest: `app/sitemap.ts`, `app/robots.ts`,
  `app/opengraph-image.tsx`, `app/icon.tsx`. See `14-metadata-and-og-images.md`.
- Structured data (JSON-LD) goes in a `<script type="application/ld+json">`
  rendered from a Server Component.

## 7. This repo's own rules

- **`src/lib/*` is pure.** No `react`, no `next/*`, no `fetch`, no
  `process.env` at module scope. Deterministic, unit-testable, importable from
  server and client alike. `calc.ts` and `pricing.ts` follow this — keep it.
- **One stylesheet**, `src/app/globals.css`, using the existing CSS custom
  properties. No new `.css` files, no Tailwind, no styled-components. Inline
  `style=` only for a computed value (e.g. a bar width).
- **Prices carry a date.** Editing any number in `pricing.ts` means you opened
  the provider's pricing page and set that model's `verifiedOn`. The UI shows
  an "unverified" warning driven by `isStale()` — don't defeat it.
- `next/image` for raster images (with dimensions), `next/link` for internal
  navigation, `next/font` for fonts (already wired in `layout.tsx`).

## 8. Before you say it's done

```bash
npm run build   # production build + typecheck — must be green
npm run lint    # next/core-web-vitals — must be clean
```

- No new `"use client"` unless §1 justifies it.
- No secret reachable from a client bundle.
- `params`/`searchParams`/`cookies()`/`headers()` all `await`ed.
- Touched a price? `verifiedOn` updated.
- Added logic to `src/lib/`? Propose `vitest` + a `*.test.ts` next to it.

## Deploying

Target is Vercel (`17-deploying.md`). `npm run build` must pass locally first.
